# Black Moon OS — the distro

Black Moon OS is an Arch-based Linux distribution: Arch's rolling
packages, the XFCE desktop, and JalOS (the teaching OS in Jal Pari)
built in. This directory holds everything needed to build its ISO.

## What is what (do not confuse the two layers)

- **Black Moon OS (this distro)** is a real, bootable Linux system:
  Arch base + XFCE + LightDM + apps. It is built with archiso.
- **JalOS (`../jalos.fg`)** is a teaching OS written in Jal Pari. It
  runs *on top of* an OS (including this one) — it is not a kernel
  and cannot boot hardware. In the distro it ships as an app:
  click "JalOS" on the desktop, or run `blackmoon-jalos`.

## What is inside the ISO

- **CLI:** full Arch CLI — `pacman`, `systemd`, `bash`, `blackmoon-install`
- **GUI:** XFCE desktop + LightDM login (live session autologs in as
  root; installed systems log in as the user you create)
- **Look: retro pixel + macOS glass.** Two ideas at once: a pixel-art
  night scene (blocky moon, stars, mountains, checkerboard ground —
  generated by `tools/make_wallpaper.py`, pure Python, no Pillow) as
  the wallpaper and boot splash, plus macOS-style glass: `picom`
  blurs what sits behind translucent windows, rounds window corners,
  and makes the panel and dock translucent; `plank` is the macOS-style
  dock at the bottom; `terminus-font` is the crisp bitmap font in the
  terminal and UI. The wallpaper is set at login by
  `blackmoon-wallpaper`, which asks xfconf for the real monitor names
  instead of hardcoding them. If picom ever fails to start, the desktop
  just falls back to plain opaque windows — nothing breaks. The
  macOS look goes further (see "macOS look" below): top menu bar,
  bottom dock with magnification, window buttons on the left, and
  the pixel wallpaper behind the login greeter.
- **Apps:** Firefox + Chromium (browse), GNOME Software + Flatpak
  (browse and install apps graphically), LibreOffice, VLC, mpv,
  GIMP, Inkscape, Evince, Mousepad, and the usual tools — plus the
  built-in Moon apps, all written in Jal Pari (see "macOS look").
- **AI (all local, no cloud account):** `ollama` for chatting with
  local LLMs (run `blackmoon-ai`; models download on first use, a
  small `qwen2:0.5b` is the suggested first one), `whisper-cpp` for
  speech-to-text, `jupyter-notebook` for experimenting — plus JalOS's
  own `ai` command, a tiny perceptron that learns the OR gate in Jal
  Pari (run `blackmoon-jalos`, then type `ai`)
- **Cybersecurity (BlackArch direction, stage 1):** 17 tools from
  official Arch repos, grouped by BlackArch category — recon/scanner
  (`nmap`, `hping`), webapp/proxy (`mitmproxy`, `sqlmap`, `gobuster`),
  forensic (`sleuthkit`, `binwalk`), reversing (`radare2`), cracker
  (`hashcat`, `john`, `hydra`, `ncrack`), wireless (`aircrack-ng`),
  sniffer (Wireshark GUI + `tshark`, `tcpdump`), networking
  (`openbsd-netcat`). `blackmoon-sec` runs a localhost-only audit
  (listening ports + a fast localhost scan + the toolkit list by
  category); anything beyond localhost is deliberately not scripted
  — use the tools directly, only with written permission for that
  target. `blackmoon-blackarch` prints the steps to add the real
  BlackArch repo after install (see below); it runs nothing itself.
- **Jal Pari:** installed on demand by `blackmoon-install-jalpari`
  (the JalOS desktop icon does this automatically on first run)
- **Installer:** `blackmoon-install` — guided, UEFI + BIOS, destroys
  the target disk, creates a real user with sudo; it also copies the
  glass theme, wallpaper, and AI/security launchers into the installed
  system (theme configs land in the new user's home, not just skel)

## macOS look (what is cloned, what is not)

The ISO boots into a desktop shaped like macOS, not just themed
like it:

- **Top menu bar:** `blackmoon-mac` (autostarted at login, and safe
  to run by hand) moves the main XFCE panel to the top edge,
  full-width, 28px, locked — applications menu, clock, and systray
  on top, as on a Mac.
- **Bottom dock:** plank, centered, 48px icons, magnification on
  hover, never hidden. The dock holds Finder, Moon Notes, Moon
  Gallery, Moon Browser, Moon Code, Terminal, Firefox, and JalOS.
- **Traffic lights:** window buttons on the LEFT in
  close/minimize/maximize order (`xfwm4` button layout `CHM|`,
  also shipped as the xfwm4 default). A bottom taskbar panel, if
  the default session created one, is auto-hidden so it never
  fights the dock.
- **Glass + wallpaper:** the existing picom glass and pixel night
  scene, plus the same wallpaper behind the login greeter.
- **Finder:** a Finder entry in the dock and menu that opens Thunar.

Built-in Moon apps (all in Jal Pari, in RED-MOON-
`examples/apps/`):

- **Moon Notes** — terminal notes: `add`, `list`, `show`,
  `search`, `remove`; one `notes.txt` in the current directory.
  From a terminal: `blackmoon-notes add Shopping "buy milk"`.
- **Moon Gallery** — takes image file paths and writes
  `gallery.html` in the current directory. Jal Pari cannot scan a
  directory (no readdir builtin), so paths are arguments; the dock
  icon opens with the pixel wallpaper as a demo.
- **Moon Browser** — a TEXT browser: fetches a URL and prints its
  readable text. Jal Pari has no rendering engine, so this is not
  a Chrome replacement.
- **Moon Code** — a line editor (`open`, `list`, `print`,
  `append`, `insert`, `delete`, `save`, `quit`), built on the new
  `read_line` builtin.

Honest limits of the clone: there is no global application menu,
no Launchpad, no Aqua window theme (no macOS theme package is in
Arch's official repos, and unverified names are never added to the
ISO list), and no macOS fonts. The Moon apps are terminal apps
with dock icons, not GUI apps — Jal Pari has no GUI toolkit, so a
real Aqua-style GUI app in Jal Pari is not possible yet. All of
the look pieces above are untested until the first boot, like
everything else profile-side.

## Toward BlackArch level (staged roadmap — honest scale)

BlackArch itself is 2000+ tools in ~50 groups (blackarch-webapp,
blackarch-scanner, blackarch-forensic, blackarch-cracker, and so on)
as an extra repo on top of Arch. Black Moon OS is NOT at that level
yet — 17 official-repo tools is a start, not parity — so the path
there is staged, and no stage claims more than it is:

- **Stage 1 — official-repo toolkit (done, in this profile).**
  17 tools across 8 BlackArch categories, all verified in Arch's
  Extra repo before being added (one bad name breaks the whole
  mkarchiso build, so nothing unverified goes in). `blackmoon-sec`
  lists them by category on the live system.
- **Stage 2 — real BlackArch repo (post-install, on your machine).**
  Run `blackmoon-blackarch`: it prints BlackArch's official
  strap.sh steps (fetch, verify the sha256 sum, run, sync), which
  you then run yourself — the script deliberately runs nothing,
  because it changes pacman.conf and the keyring. Then install
  groups one at a time (`pacman -S blackarch-webapp`, and so on).
  Do NOT install the whole `blackarch` group blindly: it is tens
  of GB. This stage only makes sense on an installed system, not
  the live session.
- **Stage 3 — parity claim (not yet).** "BlackArch level" can only
  be claimed after a built ISO boots with the chosen groups
  installed and tested — same first-build blocker as everything
  else in this profile (see Honest status).

**Deliberately NOT in packages.x86_64** (checked 27 Oct 2026, no
official-repo evidence found): metasploit, burpsuite, ffuf,
bettercap, whatweb, medusa, foremost, nuclei, and subfinder (AUR
only). These come via the BlackArch repo or an AUR helper after
first boot, never baked into the ISO list. `socat` was also left
out: no archlinux.org package-page confirmation turned up in this
check — verify with `pacman -Ss socat` on an Arch box before
adding it.

## Build the ISO (on Arch Linux only)

```
sudo pacman -S archiso
./distro/build.sh
# -> distro/out/blackmoon-*.iso
```

The ISO cannot be built on Debian/Ubuntu or in this sandbox: mkarchiso
needs pacman and Arch's repos. A GitHub Actions workflow that builds
the ISO on a runner is LIVE at `.github/workflows/build-iso.yml`
(landed 27 Oct 2026 via the Contents API): run it from the Actions
tab (it also runs on any push touching `distro/**`), and download
the ISO as the `blackmoon-iso` artifact. A reference copy is kept
at `distro/github-workflow/build-iso.yml`.

## Test it (QEMU)

```
qemu-system-x86_64 -cdrom distro/out/blackmoon-*.iso -m 4096 -enable-kvm -boot d
```

Or write it to a USB stick (destroys the stick's contents):

```
sudo dd if=distro/out/blackmoon-*.iso of=/dev/sdX bs=4M status=progress oflag=sync
```

## Install it

Boot the ISO, open a terminal, run `blackmoon-install`, follow the
prompts, reboot. After first boot: `sudo pacman -Syu`, and
`blackmoon-jalos` for the teaching OS.

## Honest status (read before trusting a build)

- **Profile written, ISO NOT built or booted yet.** The profile
  (package list, bootloader configs, live customizations) is
  complete on paper, but no ISO has been produced from it: this
  workspace is Ubuntu without mkarchiso/pacman, so the first build
  must happen on an Arch machine or runner, and the first boot must
  be tested in a VM.
- **Installer is BETA and untested** — test in a VM before any real
  disk. It wipes its target disk by design.
- **Glass theme, AI/security launchers, and installer theme-copying
  are untested too** (same reason: no first boot yet). If the pixel
  font does not resolve on some setup, GTK and the terminal fall back
  to their default fonts; if the wallpaper script finds no xfconf
  properties, pick `/usr/share/backgrounds/blackmoon-pixel.png`
  manually (right-click desktop -> Desktop Settings).
- **macOS-look pieces are untested too:** `blackmoon-mac` (top bar,
  left buttons, bottom-panel hiding), the plank settings and
  dockitems, the greeter wallpaper, and the Moon-app dock icons all
  need the first boot to prove themselves; if the top bar does not
  move, run `blackmoon-mac` by hand and check `xfconf-query -c
  xfce4-panel -p /panels/panel-1/position`.
- **Live session runs as root** (standard for live images, and the
  installed system does not). If the graphical login ever fails to
  appear, the console is still root-autologin: run `startxfce4`.
- **Package list uses official Arch repos only.** AUR packages
  (e.g. pamac, VS Code) are intentionally left out; install them
  after first boot with an AUR helper if you want them.
